Page created from the reconciliation PRD template by Anjali. Engineering addendum below was supplied by the recon maintainer on 2026-04-16. Revision history: Anjali wrote the opening scope and acceptance section; recon-maintainer-kc wrote the API, storage and recovery sections (approximately 85 percent of this page). Product approval is for the user-visible behaviour.

Acceptance: an operator who retries after a timeout must be able to find the existing export or see a clear pending state. A retry must not silently create another export. Support needs a request reference that can be copied from the screen without exposing a storage URL.

Engineering note — recon-maintainer-kc: persist the request identifier with the export job before returning acceptance. Requests with the same tenant and identifier should return the existing job record. Job creation and the outbox write share a transaction; object generation happens later. This avoids a worker racing a record that has not committed. Retain a failed job state so support can distinguish validation failure from work still running.

The recovery worker takes a lease with an expiry and only requeues jobs whose lease has elapsed. A worker that loses its lease must stop publishing its result. The current design uses the job version to reject a late completion. Review still required from the service owner before rollout; the PM does not approve this concurrency mechanism. Anjali checked the pending and failed-state wording with support on 2026-04-22.
