Route is /imports/invoices. The upload is first written to a temp file, then rows are validated. Keep the original filename only for the error screen. Do not use it as the storage key. Support sometimes sends us a file named export.csv for several different accounts.

My change normalises the tax code before lookup but keeps the original cell value for the error row. The billing reviewer asked to keep these separate; otherwise support cannot find the bad row in the customer's file. Tests have blank code, lowercase code and whitespace around a valid code. These are in the legacy import fixture folder.

Retry work follows the billing team's plan. The route gets a list of accepted chunks and does not submit them again. I initially kept this in a shared array; review changed it to request-local data. The architecture and ledger ordering are owned by billing. I can help with the route or fixtures.

For a failed deployment, ask the platform rotation to restore the previous image tag. I can run the smoke file and compare accepted row counts. Don't manually edit the database to make the count match. On 2026-08-26 support ran the smoke instructions with me; the first draft missed where to fetch the failed-row report, now added above the link in the service page.
