The base revenue fact has one row per tenant, invoice line and posting event. A credit changes the ledger value; it does not rewrite the original invoice line. Keep event period and posting period as separate columns so Finance can explain a backdated correction without moving a closed month's source rows.

Tags are many-to-many. Aggregate them before joining the fact, or put them behind a bridge model. Joining raw tags increased totals for invoices with two tags even though the invoice count looked correct. The test fixture now contains that case and checks both row count and signed value.

The incremental key includes tenant and line identity. Late updates must use the source change watermark, not only invoice creation date. Compare a full refresh with the incremental run over a window containing a late credit. Record the reconciliation totals and the source export id in the close ticket. A passing unique test alone will not catch a missing update.

The May query-profile check showed the daily invoice scan reading far more partitions than the requested dates needed. We pushed the posting-date predicate into the source CTE before considering a larger warehouse. Store the query id before and after the change, since cached runs can make this comparison misleading.

2026-10-09: Finance used these steps to reproduce the September backdated-credit adjustment. Source net amount, base fact and adjustment model reconciled separately. The adjustment remains visible in the close report rather than being folded into the invoice measure.
