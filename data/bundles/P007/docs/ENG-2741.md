The pilot answers questions about one statement period for an authenticated tenant. Tenant identity comes from the request context, never the question. We filter candidates before ranking. Filtering after the top-k step both wastes slots and makes empty results hard to distinguish from access failures. Cache entries carry tenant, ledger period and index revision. The February cache incident came from leaving period out of that key.

Each answer includes invoice references and amounts. The verifier checks reference membership, currency and whether the cited chunk contains the claim. A valid invoice reference alone is insufficient: we saw correct totals attached to an unrelated invoice. If the check fails, return the no-answer response. Do not ask generation to repair the citation repeatedly; that hid failures in the first pilot report.

The evaluation set has 180 labelled questions, including missing invoice, stale index, conflicting currency and instructions embedded in invoice text. We keep the rejected answers in the denominator and report coverage separately. An evaluator update cannot overwrite last release's report. Save prompt, index settings, model revision and evaluation version together.

2026-08-20 pilot check: replayed the removed-invoice slice after tombstone propagation. No removed invoice references remained in those 34 cases. This is a regression slice, not a claim about all unsupported answers. Roll back the whole configuration bundle if stale-source answers increase after deployment. Rohit ran the rollback using these steps in staging on 2026-08-19; saved report ids matched the previous release.
