This page records the network checklist used when creating the pilot environment. The application must reach the model gateway and retrieval store. Inbound access is through the standard service ingress. The platform reviewer checks the actual security groups and service-account permissions before any production request is enabled.

The environment request includes expected outbound destinations, storage locations and data retention needs. Development and production use separate identities. Test payloads must not include bank account references copied from a support case. Use the sanitised sample set already approved for the pilot. The gateway configuration is linked from the deployment ticket so the on-call engineer can find the active revision.

A failed gateway call should be recorded as an application error, with a request identifier that can be followed through the logs. A tenant's question text must not become a metric label. Keep the error label bounded and put the diagnostic detail into the access-controlled trace. The logging owner checks the redaction rule before the pilot is opened to another tenant.

For rollback, use the previous deployment revision and verify a test request using the standard smoke-test account. Changes to the VPC layout, routes, firewall rules and managed identities require a platform change request. This checklist does not authorise an application owner to make those changes. The platform team's network diagram and reviewed Terraform plan are attached to the original request.
