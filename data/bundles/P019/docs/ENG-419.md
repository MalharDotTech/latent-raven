Use two test tenants and one revoked user. Each tenant needs one attachment with a distinct filename so a metadata leak is visible even when the response does not contain the file body. These are disposable test records; don't paste production attachment URLs into SEC.

First request the download link as a member of tenant A. Then repeat with tenant B's token and the same object identifier. The second request must fail before signing a storage URL. An opaque object key is not an access check. Repeat with a user removed from tenant A after the first successful request. This catches code that trusts membership cached at login.

For each denial, inspect the response body as well as the status. We previously returned the filename with a forbidden response. A revoked user should not obtain a new signed URL; an already issued URL has a separate expiry limitation that the service owner must document. Do not claim revocation is immediate if the storage URL remains valid until expiry.

Billing applied the membership gate and the metadata filter. Recon maintainers used this matrix for export attachments and found one missing revoked-user case in their own tests. I reviewed both sets of results before the exception was removed.

September check: support followed the curl sequence in a clean sandbox without needing developer access. The first attempt had an expired token; the instructions now separate authentication failure from tenant denial. Java fixture lifecycle changes were reviewed by the billing maintainer. My approval covers the access behaviour and evidence of the negative tests.
