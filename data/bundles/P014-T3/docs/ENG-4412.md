# Mobile release train - checklist and rollback

Releases go out every 2 weeks (Tuesday cut, Thursday store rollout). Owner of the week is on the rota in PEOPLE space.

## Before cut
1. All MOB tickets for the train in "Ready for release". Nothing half-merged behind a flag that is not off by default.
2. `main` is green on GitHub Actions (jest + detox smoke on the android emulator job). iOS detox smoke runs on Bitrise, it is slower, wait for it.
3. Bump version with `yarn release:prepare <x.y.z>`. This updates `package.json`, android `versionName`, iOS `MARKETING_VERSION`. Build numbers are set by fastlane from the CI run number, do not edit by hand.
4. Changelog: generated from PR titles since last tag. Fix the ugly ones before generating (squash titles are often `WIP`).

## Cut and submit
- Tag `v<x.y.z>`; release bot opens the release PR. The lead merges it.
- `fastlane android beta` -> internal track. `fastlane ios beta` -> TestFlight. Wait for processing, can take 20-40 min.
- Smoke on a real low-end Android (we keep a Redmi 9 in the Hyderabad office) and one iPhone SE. Check cold start deeplink `kestrel://invoice/:id`.

## Rollout
- Play: staged 5% -> 20% -> 50% -> 100% over 3 days, watch Crashlytics crash-free users. Halt if < 99.3%.
- App Store: phased release on.
- CodePush is only for JS-only hotfixes, and not allowed for changes touching native modules.

## Rollback
- Android: halt rollout, promote previous build from the Play console. iOS: remove from sale is not enough, submit expedited review of previous build as new version.
- If a JS hotfix went out through CodePush, `appcenter codepush rollback` first, then decide.
- Post incident note in ENG space, link the INC if customer facing.

## Known gotchas
- Hermes + reanimated mismatch after RN upgrades; clear pods and gradle cache before blaming the code.
- FCM token refresh on Android 13 needs the POST_NOTIFICATIONS permission prompt, it silently fails otherwise.
